# Blind row-find judge — content pipeline list

Captures reviewed: split-content-1440-top/mid-lane/deep-lane.png, split-content-390-top/mid-lane/deep-lane.png, split-content-1440-mattan-top.png.

## 1440 — top band (Ivan / Ideas, score-led rows)
1. **Three-second test**: The only thing that answers "where are the review-waiting rows" is a stat line — "●19 needs review" — sitting inside a rounded stats card near the top, next to "60 ideas / 2 scheduled / 109 published" and a segmented progress bar. It's a number+label pair with a small gray dot, same visual weight as the other three counts (no color pop, no distinct icon). It tells you a QUANTITY exists, not WHICH rows below are them — the 60-row Ideas list underneath has no per-row "needs review" flag (every visible row looks identical in structure: score / title / tag chips / "9d ago"). You'd have to read the caption "60 rows at reviewing" to learn the whole visible list already IS that state, which is a sentence, not a glanceable mark.
2. **Error state**: No row in the list is marked errored. The only red is the aggregate alert card above the list — "39 (red) · 4 errored · 35 elsewhere" in a red-outlined pill with a chevron. Marked by red numeral + red border on a summary card, not on any individual row.
3. **Anchor rail**: Every idea row leads with a large score number (69.5, 68.32, 66.82…) at a fixed x — that is a straight rail, and the eyes do track it cleanly since it's numeric and right-aligned to a shared width. But it's a score, not an avatar/thumbnail/chip/number-of-anything — it doesn't encode status, source, or type. After the score, everything else (tag chips, date) is same-style text, so the rail helps scanning rows but not classifying them.

## 1440 — mid/deep-lane (Resources)
Rail breaks here: most rows (Story-First Brief, B2B Paid Media Checklist, Reactive AM Audit, Account Growth Audit, Outdoor DTC Profit Leak Audit, 4-Channel Outreach Checklist…) have **no leading mark at all** — title text starts flush at the card's left edge. A minority of rows (R1A smoke test, Agency Capacity Calculator, Start form-Waitlist, the scoping framework, AI Governance Scorecard) suddenly gain a square thumbnail/avatar image on the left, which shoves their title text ~56px right of where the text-only rows start. Scanning down, the eye zigzags between two different left margins depending on whether that particular row happens to carry media. Status (PENDING / PUBLISHED / DISQUALIFIED) is a plain gray-outline text chip — same visual style regardless of which word is inside, so status is not color-coded; you must read the word.

## Mattan lane (1440-mattan-top)
5. Status without reading sentences: **No.** Every row does start with a same-size square mark at a fixed x (a real discipline here — Don Pablo case study has a green-tinted carousel thumbnail, AI Aisle Field Guide a white one, $6k Meta teardown a black/orange one, the ROAS row an actual headshot avatar, the two RISE DTC rows a plain teal/green color bar instead of an image). That rail is consistent for THIS section. But the mark itself is a content thumbnail/avatar, not a status indicator — it tells you what the post looks like, not its QA state. The actual state lives in a text badge next to the title — "PASS 79", "NO QA", "NEEDS_REGENERATE 71", "PASS 83" — all rendered in the same neutral gray chip style, so "PASS" and "NEEDS_REGENERATE" look like siblings until you read them. The one genuinely glanceable element is the section header itself: "NEEDS REVIEW  1/11" with a small amber/orange square dot before the count — that IS a real, colored, section-level signal, the best one seen in any capture.

## 6. Verdicts

**1440 — FAIL.** Row-find (e.g., "which rows need review") is not achievable in ~3 seconds by scanning marks alone outside the one section that has an explicit "NEEDS REVIEW" header (Mattan lane). In the main Ideas/Resources lists the anchor rail is either a score number (encodes nothing about status) or absent/inconsistent, and every status word renders as the same neutral gray chip — deciding feature: no color- or shape-coded status marker exists anywhere on a row itself, only on section headers or an aggregate stat card, and those aren't wired to most of the lists shown.

**390 — FAIL, more severe.** Same missing status coding, plus the already-thin thumbnail rail present at 1440 mostly disappears — deep-lane rows are pure stacked text with nothing left of the title. Deciding feature: on mobile even the partial visual rail is gone, so scanning falls back entirely to reading each row's tag word.
